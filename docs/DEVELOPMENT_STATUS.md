- 同一台机器、相同自包含单文件和空白配置下空闲 60 秒，托盘冷启动工作集由优化前的 208.6 MB 降至 27.1 MB（下降 87.0%），私有内存为 165.4 MB；

- 从已回收到 9.1 MB 工作集的托盘状态重新打开窗口耗时约 447 ms，窗口响应正常；工作集和私有提交量是不同指标，回收不会等量降低私有内存；
- `--minimized` 启动不创建主窗口，关闭到托盘会释放窗口、ViewModel、当前页面、窗口级图标缓存和用完的托盘菜单资源。

## 4. 已知限制与技术债

### P0：可靠性

- 自动化测试使用假的 `IAudioService`，尚没有覆盖真实 Core Audio、COM 和 WPF 的集成测试。
- 蓝牙连接、HDMI 热插拔、休眠恢复、应用频繁创建/销毁会话时仍需要更长时间的压力测试。
- WPF 窗口首次打开会初始化渲染和 JIT 缓存；进入托盘后驻留工作集会主动归还，但私有提交内存不会全部下降，Windows 也可能按需重新调入后台代码页。
- NAudio 会话事件没有完整暴露原生 `EventContext`；当前依靠恢复窗口抑制学习，后续可用原生 `IAudioSessionEvents` 互操作进一步收紧竞态窗口。
- 音频事件处理会忽略端点切换中的瞬态异常。应逐步增加可控的本地诊断记录，同时避免因为预期的设备消失而打扰用户。

### P1：声音功能覆盖

- 合成器只显示当前默认输出端点上已经存在的活动音频会话。
- 被 Windows 固定路由到其他设备的应用不会出现在当前端点合成器中。
- 输入设备没有每设备 Profile，也没有应用级录音音量模型。
- 音频格式、测试音、增强、空间音效、设备重命名和单声道音频仍由 Windows/驱动页面处理。
- 尚未实现 Realtek 插孔状态识别、设备别名，以及蓝牙 Stereo、Hands-Free、LE Audio 的物理设备合并。

### P2：发布与维护

- 安装程序没有代码签名证书。
- 没有崩溃报告、CI 或可重复的远程构建证明；更新功能仅使用 GitHub 公共接口。
- 安装版更新依赖 Release 同时提供命名正确的 x64 Setup 和 `SHA256SUMS.txt`；便携版仍需用户手动下载替换。
- 没有 Profile 导入、导出、重置单设备配置或 UI 中查看保存记录的功能。
- 当前只有中文为主的用户界面，尚未完成应用本体国际化。

## 5. 推荐路线图

### 里程碑 A：预览版稳定性

1. 建立真实设备手工回归矩阵：扬声器、有线耳机、蓝牙、HDMI；
2. 重复执行系统音量、应用音量、静音和设备切换压力测试；
3. 为音频事件增加可开关的本地诊断日志；
4. 针对端点消失和会话过期增加集成级验证；
5. 收集并修复预览版用户报告的崩溃和恢复错误。

### 里程碑 B：更完整地替代 Windows 音量入口

1. 明确能安全直接控制的设备属性 API；
2. 增加设备别名和用户友好的端点识别；
3. 评估输入设备 Profile；
4. 评估应用跨设备路由控制；
5. 对只能由系统或驱动处理的功能继续使用清晰的 Windows 设置入口。

### 里程碑 C：正式版发布工程

1. 增加 CI 构建、测试和发布资产校验；
2. 设计配置迁移、导入导出和回滚；
3. 引入代码签名；
4. 为更新下载与安装交接增加签名校验和 CI 发布资产证明；
5. 完成应用本体国际化和无障碍检查。

## 6. 下一次开发建议

如果用户没有指定新功能，优先从“里程碑 A”开始，不要直接扩展大量 UI。推荐的下一项是：为真实 Core Audio 事件增加可开关的本地诊断记录和手工压力测试清单，以便定位设备切换、外部系统音量变化和会话生命周期问题。
