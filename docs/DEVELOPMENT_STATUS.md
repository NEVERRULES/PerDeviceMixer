## 4. 已知限制与技术债

### P0：可靠性

- 自动化测试使用假的 `IAudioService`，尚没有覆盖真实 Core Audio、COM 和 WPF 的集成测试；手工矩阵见 [真实设备回归清单](REAL_DEVICE_REGRESSION.md)。
- 蓝牙硬件和 Windows 蓝牙栈在输出端点变为 Active 前仍可能耗时；应用侧已消除设备事件队列堆积，但蓝牙连接、HDMI 热插拔、休眠恢复、应用频繁创建/销毁会话时仍需要更长时间的压力测试。
- WPF 窗口首次打开会初始化渲染和 JIT 缓存；进入托盘后驻留工作集会主动归还，但私有提交内存不会全部下降，Windows 也可能按需重新调入后台代码页。
- NAudio 会话事件没有完整暴露原生 `EventContext`；当前依靠恢复窗口抑制学习，后续可用原生 `IAudioSessionEvents` 互操作进一步收紧竞态窗口。
- 音频事件已顺序处理并支持可控本地诊断，但仍需使用原生 `IAudioSessionEvents` 的 `EventContext` 消除应用音量恢复的时间窗口。

### P1：声音功能覆盖

- 合成器只显示当前默认输出端点上已经存在的活动音频会话。
- 被 Windows 固定路由到其他设备的应用不会出现在当前端点合成器中。
- 输入设备没有每设备 Profile，也没有应用级录音音量模型。
- 音频格式、测试音、增强、空间音效、设备重命名和单声道音频仍由 Windows/驱动页面处理。
- 尚未实现 Realtek 插孔状态识别、设备别名，以及蓝牙 Stereo、Hands-Free、LE Audio 的物理设备合并。
- 耳机电量当前只支持 Beats Fit Pro，来自厂商 BLE 广播且按 10% 档位呈现；未安装厂商驱动，不提供降噪、通透、佩戴检测或按键控制。
- Windows 常见的随机蓝牙地址无法稳定映射到音频端点，因此当前用“默认端点型号匹配 + 广播连续性过滤”降低误配；附近同时存在多副同型号 Beats Fit Pro 时仍需真实场景验证。

### P2：发布与维护

- 安装程序没有代码签名证书。
- 没有崩溃报告或可重复的签名发布证明；CI 仅验证还原、格式、构建和测试，更新功能仅使用 GitHub 公共接口。
- 安装版更新依赖 Release 同时提供命名正确的 x64 Setup 和 `SHA256SUMS.txt`；便携版仍需用户手动下载替换。
- 没有 Profile 导入、导出、重置单设备配置或 UI 中查看保存记录的功能。
- 当前只有中文为主的用户界面，尚未完成应用本体国际化。
