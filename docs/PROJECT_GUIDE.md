# PerDeviceMixer 项目总手册

本文档面向产品维护者、开发者和首次接手项目的新对话。用户安装和操作说明见根目录的 [README](../README.md)，当前完成度和路线图见 [开发状态](DEVELOPMENT_STATUS.md)。

## 1. 项目定位

PerDeviceMixer 是一款纯本地 Windows 音量管理器。它解决的核心问题是：Windows 能为不少输出设备记住主音量，却不能自然地为每个输出设备维护一套完整、自动学习的应用混音状态。

项目采用“设备即配置”的模型：

```text
笔记本扬声器
├─ 主音量和主静音
├─ 系统声音
├─ 浏览器
└─ 播放器

有线耳机
├─ 主音量和主静音
├─ 系统声音
├─ 浏览器
└─ 播放器
```

用户正常调整音量，程序自动学习当前输出设备的状态；设备切换回来时，程序自动恢复，不要求用户创建或选择 Profile。

## 2. 产品原则

### 2.1 纯本地

- 不需要账号。
- 不上传音量配置。
- 不包含遥测、远程同步、后台服务器或项目自建 API。
- 仅更新检查、项目链接和问题反馈会访问 GitHub；更新请求不携带配置或音频数据。
- 配置保存在 `%LocalAppData%\PerDeviceMixer\profiles.json`。
- 仅在关闭阶段发生异常时，可能在 `%LocalAppData%\PerDeviceMixer\logs` 写入本地错误日志。

### 2.2 未知状态优先保持不变

第一次遇到输出设备或应用时，程序读取并保存 Windows 当前值，不把其他设备或其他应用的配置强行套用过去。只有当前设备已经存在记录时才执行自动恢复。

### 2.3 自动学习与自动恢复分离

设置中可以分别控制：

- 是否学习用户和其他音量工具做出的修改；
- 是否在切换设备时恢复；
- 是否在新音频会话出现时恢复；
- 是否保存静音状态；
- 写入配置前的去抖延迟。

### 2.4 如实区分应用能力和系统入口

当前应用直接实现了设备选择、主音量、应用音量、静音、默认输入设备和输入主音量。音频格式、增强、空间音效、设备重命名等仍由 Windows 或驱动管理，应用目前只负责打开相应设置入口。

## 3. 当前用户界面

### 音量合成器

- 首页下拉框选择默认输出设备；
- 控制当前默认输出设备的主音量和静音；
- 按应用聚合活动音频会话；
- 控制应用音量和静音；
- 从可执行文件提取应用图标，失败时使用通用图标。

### 声音设备

- 枚举输出和输入设备；
- 设置默认输出或默认输入设备；
- 控制当前默认输入设备的音量和静音；
- 打开设备属性、声音设备、蓝牙和单声道音频设置。

### 设置与后台

- 自动学习、自动恢复和新会话恢复开关；
- 静音状态保存和保存延迟；
- 当前用户开机自启动；
- 关闭时退出或最小化到托盘；
- 所有设置自动去抖保存，并显示待保存、成功或失败状态；
- 深色 WPF 托盘中打开窗口、切换主静音、切换输出设备、检查更新、反馈问题、访问项目主页和退出；
- 可配置 GitHub Releases 自动检查间隔，安装版可校验后启动可见安装向导，便携版打开 Release 页面；
- 单实例运行，重复启动会唤醒现有窗口。

## 4. 架构

```text
PerDeviceMixer.App (ApplicationController / WPF / 原生托盘 / GitHub 更新)
                 |
                 v
PerDeviceMixer.Core (MixerEngine / Profile / 策略)
                 ^
                 |
PerDeviceMixer.Audio (NAudio / Core Audio / COM)

PerDeviceMixer.Probe  -> 音频枚举与事件诊断
PerDeviceMixer.Core.Tests -> 核心策略和存储测试
PerDeviceMixer.App.Tests  -> 更新、版本和下载校验测试
```

### `PerDeviceMixer.Core`

- 定义音频端点、会话、通知和服务接口；
- 维护每设备 Profile；
- 编排捕获、自动学习、设备恢复和新会话恢复；
- 使用单个有界保存工作器合并写入，避免每次变化创建独立任务；
- 提供统一保存状态事件，并由 `Flush/FlushAsync` 保证退出写入；
- 通过 `IProfileStore` 进行原子保存和损坏文件隔离。

此层应保持可测试，不直接引用 WPF、NAudio 或 Windows 设置 UI。

### `PerDeviceMixer.Audio`

- 枚举播放和录音端点；
- 读取和设置端点主音量、静音及应用会话音量；
- 通过 `PolicyConfig` 设置 Windows 默认端点；
- 监听默认设备、设备集合、端点音量、新会话和会话音量变化；
- 在专用音频线程上管理 Core Audio 和 COM 对象。

### `PerDeviceMixer.App`

- `ApplicationController` 在应用级持有 `MixerEngine`、托盘和更新调度器；
- 主窗口和 ViewModel 按需创建，关闭到托盘时销毁，页面通过 DataTemplate 只加载当前导航项；
- 应用图标只在窗口生命周期内缓存，窗口销毁时释放；
- 进入纯托盘状态约 2 秒后执行一次托管堆整理和 Windows 工作集回收；重新打开窗口、显示反馈对话框或更新任务运行时会取消或推迟回收；
- 回收只在进入托盘、托盘临时界面关闭和后台更新结束等状态边界触发，不做周期性 GC；它降低的是驻留工作集，私有提交内存不会等量下降，重新打开窗口需要重新调入页面；
- 使用 Windows Shell 托盘接口和 WPF `ContextMenu`，Explorer 重启后重新注册图标；
- 使用 Shell 标准悬停提示显示当前输出设备、主音量和静音状态；提示随默认设备和主音量事件刷新，并限制在 `NOTIFYICONDATA.szTip` 的长度范围内；
- 管理单实例、当前用户启动项、GitHub 更新、安装交接和支持链接；
- 通过 `ms-settings:` 打开 Windows 提供的高级声音页面。

### `PerDeviceMixer.Probe`

面向开发阶段的诊断工具。默认读取当前设备和会话，并可观察 Core Audio 事件。它不是普通用户发布包的一部分。

## 5. 核心数据模型

`MixerProfileDocument` 当前使用 `SchemaVersion = 2`，包含全局设置和按 Endpoint ID 索引的设备配置。读取 v1 时保留所有设备与应用音量，并补齐更新设置；非法检查间隔回退为 24 小时。

```text
MixerProfileDocument
├─ SchemaVersion
├─ Settings
└─ Devices[EndpointId]
   ├─ Name
   ├─ MasterVolume
   ├─ MasterMuted
   ├─ LastUpdatedUtc
   └─ Applications[ApplicationKey]
      ├─ DisplayName
      ├─ ExecutablePath
      ├─ Volume
      ├─ Muted
      └─ LastUpdatedUtc
```

应用标识的优先顺序是：

1. 完整可执行文件路径：`path:...`；
2. 进程名：`exe:...`；
3. 会话标识：`session:...`；
4. 系统声音固定为 `system:sounds`。

同一个应用的多个活动会话共享一个应用配置，调整会应用到所有匹配会话。

## 6. 关键运行流程

### 启动

1. 加载 `profiles.json`；
2. 注册音频事件并开始监听；
3. 获取当前默认输出设备快照；
4. 已知设备且启用自动恢复：恢复后再次捕获；
5. 未知设备：只捕获 Windows 当前状态；
6. 通知界面刷新。

### 用户调整音量

1. ViewModel 调用 `MixerEngine`；
2. 引擎立即设置 Windows 音量；
3. 若启用自动学习，同步更新内存 Profile；
4. 到达去抖时间后原子保存配置。

### Windows 或其他软件调整音量

1. Core Audio 通知携带设备、应用、音量和静音状态；
2. 引擎忽略由自身恢复引起的通知；
3. 更新对应设备和应用的 Profile；
4. 去抖保存并刷新界面。

### 切换默认输出设备

1. 收到默认端点变化通知；
2. 对已知设备执行恢复；
3. 对未知设备仅学习当前值；
4. 捕获恢复后的最终状态并刷新 UI。

### 新音频会话出现

如果当前设备已经保存该应用，且启用了新会话恢复，则恢复音量与静音；未知应用保持 Windows 当前值。

## 7. 配置可靠性

- 保存时先写同目录临时文件，再替换正式文件；
- 无效 JSON 会被改名为 `.corrupt-*`，程序回到默认配置；
- 保存前保留当前未运行应用的历史记录；
- 保存延迟限制在 100–5000 ms；
- 设置和音量变化先更新内存，再由单工作器异步写入；退出和安装交接前强制刷新；
- 会话恢复抑制记录会按时间清理，并限制最大容量；
- 蓝牙、HDMI 或休眠切换期间端点短暂消失属于预期瞬态，下一次通知会继续刷新。

## 8. 更新与支持边界

- 使用无 Token 的 GitHub Releases 列表 API，10 秒超时；正式版忽略预发布，预览版可接收预发布或正式版；
- 自动检查默认每 24 小时，可选 6、24、72、168 小时；失败后至少等待 1 小时；
- 只接受 GitHub HTTPS 下载地址、匹配的 x64 Setup、合理文件大小和 `SHA256SUMS.txt` 中的 SHA-256；
- 安装版下载到本地更新目录，校验后刷新配置、释放单实例 mutex 并打开可见安装向导；便携版不自动覆盖程序文件；
- 问题反馈默认只包含版本、Windows、架构和安装类型；可选设备摘要仅含名称和数量，不含设备 ID、用户名、应用列表、Profile 或日志。

## 9. 安装与发布结构

当前支持 Windows x64：

- 自包含 EXE 安装程序：按当前用户安装，无需管理员权限；
- 自包含单文件便携 ZIP：解压即用；
- SHA-256 校验文件；
- Inno Setup 安装器支持简体中文和英文；
- 安装程序尚未数字签名。

发布脚本和详细流程见 [贡献指南](../CONTRIBUTING.md)。
