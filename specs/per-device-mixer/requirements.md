# PerDeviceMixer V1 Requirements

## Problem and scope

Windows 会为部分输出设备记住主音量，但不会为每个设备分别保存完整的应用混音状态。V1 以默认播放端点为配置边界，自动学习并恢复主音量、静音和每应用音量。

## User stories

1. 作为多音频设备用户，我希望切换输出设备后立即恢复该设备的整套混音状态。
2. 作为普通用户，我希望平时使用 Windows 音量合成器调整后，软件自动学习，不需要手动保存 Profile。
3. 作为稍后启动应用的用户，我希望新出现的音频会话获得当前设备中已保存的音量。
4. 作为注重隐私的用户，我希望配置只保存在本机，且未知应用不会被擅自修改。

## Acceptance criteria

1. 当默认播放端点变化时，系统应在收到 Core Audio 通知后恢复新端点已保存的主音量和应用音量。
2. 当用户或其他软件改变当前端点的主音量或会话音量时，系统应在去抖延迟后保存当前端点配置。
3. 当新音频会话出现且当前设备已有该应用记录时，系统应恢复该应用的音量与静音状态。
4. 当应用在当前设备中从未保存时，系统应保持 Windows 当前值不变。
5. 当配置写入被中断时，系统不应破坏上一份完整配置；无效 JSON 应被隔离并回退到默认配置。
6. 当多个会话属于同一可执行程序时，界面应按应用聚合显示，并把调整应用到所有匹配会话。
7. 当没有默认播放端点时，应用应保持运行并显示可恢复状态，而不是崩溃。

## Non-goals for the first usable build

- 同一 Endpoint 内部的 Realtek 插孔状态识别
- 蓝牙 Stereo、Hands-Free、LE Audio 的物理设备合并
- Windows 服务和自动更新
- 在应用内直接实现所有由 Windows 或设备驱动提供的格式、增强和空间音效控制
- 云同步、账号或遥测
